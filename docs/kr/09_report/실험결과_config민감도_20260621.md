# Config별 위험도 민감도 실험 결과 - 2026-06-21

## 1. 실험 목적

Config별 민감도 실험의 목적은 동일한 DDL과 동일한 작업 부하 조건에서도 서버 처리 여력 설정이 달라지면 MigraGuard의 위험도 판단이 달라지는지 확인하는 것이다. 이는 정확도 검증이 아니라, 계산 구조가 `C_max`, `MuMax`, 디스크 입출력 처리량 변화에 반응하는지 확인하기 위한 실험이다.

기존 `lowcapacity.yaml`, `default.yaml`, `highcapacity.yaml`은 처리 여력뿐 아니라 임계값, 기본 위험도, 잠금 영향도까지 함께 바뀐다. 이 경우 위험도 변화의 원인이 서버 처리 여력 때문인지 판정 정책 때문인지 구분하기 어렵다. 따라서 이번 실험에서는 controlled config를 별도로 만들고, Safe·Warning·Danger 임계값과 계산 계수는 고정한 채 `C_max`, `MuMax`, 디스크 입출력 처리량만 변경하였다.

## 2. 실험 설정

| 항목 | 값 |
|---|---|
| 대상 DDL | DDL-1 ~ DDL-6 |
| 작업 부하 입력 | 1000 TPS 실험에서 수집한 `orders_mixed` 지표 |
| 대상 테이블 | `orders` |
| 테이블 규모 | 약 1,000,000 rows |
| 분석 방식 | MigraGuard 일반 분석 |
| 결과 CSV | `experiments/benchmark/results/config_sensitivity_20260621/config_sensitivity_summary.csv` |

각 DDL 분석 전에는 benchmark DB를 초기화하였다. DDL 자체는 실행하지 않고, 동일한 DB 상태에서 MigraGuard의 사전 분석 결과만 비교하였다.

## 5. 해석

DDL-2는 config 차이가 가장 잘 드러난 사례이다. Low Capacity에서는 RiskScore가 3090으로 Danger였지만, Default에서는 61.80으로 Warning, High Capacity에서는 3.05로 Safe가 되었다. 같은 DDL과 같은 작업 부하라도 서버 처리 여력과 디스크 처리량이 커지면 `T_ddl`, `T_block`, `C_peak`가 함께 낮아져 위험도가 완화된다는 점을 보여준다.

DDL-1도 Low Capacity에서는 Danger였지만 Default와 High에서는 Safe로 바뀌었다. 이는 단순한 메타데이터성 변경도 처리 여력이 매우 낮은 환경에서는 위험하게 계산될 수 있음을 보여준다.

DDL-4, DDL-5, DDL-6은 High Capacity에서도 Danger가 유지되었다. 다만 RiskScore는 Low 대비 크게 낮아졌다. 이는 일부 DDL은 처리 여력이 커져도 정적 기본 위험이나 강한 잠금 영향 때문에 여전히 위험 후보로 남을 수 있음을 의미한다.

주의할 점은 DDL-3이다. DDL-3은 실제 실행 실험에서 P99 응답 지연 증가가 확인된 일반 인덱스 생성 DDL이지만, High Capacity 설정에서는 Safe로 계산되었다. 이는 config 값이 지나치게 큰 경우 실제 위험을 과소평가할 수 있음을 보여준다. 따라서 config 값은 임의로 크게 설정하는 값이 아니라, 실제 부하 시험과 운영 지표를 바탕으로 보정해야 한다.

## 6. 보고서 반영 방향

보고서에는 전체 18개 결과를 모두 상세히 넣기보다, 변화가 뚜렷한 DDL-2와 한계가 드러나는 DDL-3을 중심으로 제시하는 것이 적절하다.

| 대표 사례 | 보고서에서 보여줄 내용 |
|---|---|
| DDL-2 | Low → Default → High로 갈수록 Danger → Warning → Safe로 완화 |
| DDL-3 | High Capacity에서는 Safe로 내려가지만 실제 실험에서는 P99 증가가 있었으므로 config 보정 필요성 강조 |
| DDL-4~6 | 처리 여력이 커져도 Danger가 유지되는 DDL 유형이 있음을 요약 문장으로만 언급 |

이 실험의 결론은 다음과 같이 제한하는 것이 안전하다.

> Config별 비교 결과, MigraGuard는 동일 DDL과 동일 작업 부하에서도 서버 처리 여력 설정에 따라 RiskScore를 다르게 산출하였다. 다만 High Capacity 설정에서 실제 위험이 있었던 DDL-3이 Safe로 낮아지는 사례도 확인되어, `C_max`, `MuMax`, 디스크 처리량은 임의값이 아니라 실제 부하 시험과 운영 관측에 기반해 보정해야 한다.
