# 🛡️ MigraGuard 요구사항 명세서 (Requirements Specification)

**버전:** 3.8.0 (Research-Grade Architecture)  
**프로젝트 성격:** PostgreSQL 마이그레이션 리스크 분석 및 자동 게이트키핑 도구

---

## 1. User Stories

### Epic 1: 마이그레이션 리스크 분석 (Analyze)
**Goal:** 개발자가 SQL 배포 전, 운영 환경의 부하를 반영한 정량적 위험도를 확인하고 장애를 예방한다.

**US-01 : 사용자는 특정 SQL 파일의 마이그레이션 리스크를 분석할 수 있다.**
- **As a :** 서비스 개발자
- **I want to :** 배포 예정인 SQL 파일을 CLI 도구에 입력하여 분석을 실행하여
- **So that :** 해당 쿼리가 운영 환경에서 락(Lock) 경합으로 인한 장애를 유발하지 않도록 사전 예방하고 싶다.

**US-02 : 사용자는 분석 결과 리포트를 다양한 형식으로 추출할 수 있다.**
- **As a :** 서비스 개발자 / DevOps 엔지니어
- **I want to :** 분석 결과를 콘솔, 마크다운, 또는 CSV 포맷으로 저장하여
- **So that :** PR 코멘트 활용이나 연구 데이터 통계 분석에 활용하고 싶다.

---

### Epic 2: 운영 지표 수집 및 관리 (Agent)
**Goal:** 운영 데이터베이스의 트래픽 패턴을 지속적으로 학습하여 분석의 근거 데이터를 확보한다.

**US-03 : 사용자는 백그라운드에서 실행되는 지표 수집 에이전트를 가동할 수 있다.**
- **As a :** DBA / 시스템 운영자
- **I want to :** MigraGuard 에이전트를 상시 실행하여
- **So that :** 운영 DB의 실시간 및 과거 피크 트래픽 데이터를 지속적으로 누적할 수 있다.

---

### Epic 3: 시뮬레이션 및 연구 (Simulation)
**Goal:** 실제 DB 없이도 가상의 시나리오를 통해 시스템의 한계를 테스트하고 연구 데이터를 생성한다.

**US-04 : 사용자는 YAML 시나리오를 바탕으로 가상 워크로드 데이터를 생성할 수 있다.**
- **As a :** 연구원 / 개발자
- **I want to :** 수학적 모델이 반영된 가상 데이터를 즉시 생성하여
- **So that :** 다양한 부하 상황에서의 리스크 엔진 동작을 오프라인에서 검증하고 싶다.

---

## 2. System Stories (Technical Specification)

**SYS-01 : 전략 패턴 기반의 모듈형 리스크 엔진**
- **As a :** 리스크 엔진
- **I want to :** 분석 단계별로 독립적인 Evaluator 객체를 실행하여
- **So that :** 새로운 분석 지표 추가 시 기존 코드의 수정 없이 유연하게 확장할 수 있다.

**SYS-02 : 전 계층 Context 전파를 통한 자원 제어**
- **As a :** 시스템
- **I want to :** 모든 I/O 요청에 `context.Context`를 전달하여
- **So that :** 타임아웃이나 중단 신호 발생 시 DB 커넥션 등 자원을 안전하게 관리할 수 있다.

**SYS-03 : 표준화된 에러 코드 체계 (`MG-XXX`)**
- **As a :** 운영자
- **I want to :** 발생하는 모든 예외 상황에 대해 고유한 에러 코드를 확인하여
- **So that :** 문제의 원인을 신속하고 정확하게 진단할 수 있다.
