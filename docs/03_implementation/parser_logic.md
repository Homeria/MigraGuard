# ⚙️ MigraGuard 구현 상세 (Implementation Details)

본 문서는 MigraGuard의 핵심 로직인 **부하 생성 엔진**과 **지표 산출 알고리즘**의 상세 구현 명세를 다룹니다.

---

## 1. 부하 생성 엔진 (`internal/simulation/`)

### 1.1. 목적
실제 이커머스 서비스의 트래픽 패턴을 정밀하게 모사하여, 데이터베이스의 락 경합 및 성능 저하 상황을 재현하고 리스크 엔진의 정확도를 검증합니다.

### 1.2. 워커 풀 아키텍처 (Worker Pool)
- **동시성 제어**: 설정된 `Concurrency` 값에 따라 다중 고루틴 워커를 할당합니다.
- **독립 세션**: 각 워커는 독립적인 데이터베이스 커넥션을 유지하여 실제 다중 사용자 접속 환경을 극대화합니다.

### 1.3. 24시간 트래픽 곡선 (Sine Wave)
현실적인 일간 트래픽 변화를 위해 다음과 같은 사인파 공식을 적용합니다.
- **공식**: $\text{Intensity} = \frac{\sin(\frac{\pi \times (\text{hour}-9)}{12}) + 1.5}{2.5}$
- **동작**: 현재 시스템 시간을 기준으로 부하 강도를 0.2(저부하)에서 1.0(피크) 사이로 자동 조절합니다.

### 1.4. 비즈니스 시나리오
- **상품 탐색 (Browse)**: 다량의 `SELECT` 쿼리를 발생시켜 읽기 부하를 형성합니다.
- **주문 처리 (Order)**: 주문 생성, 재고 차감, 포인트 적립 등 트랜잭션을 수반하는 `INSERT`/`UPDATE` 쿼리를 발생시켜 쓰기 부하와 락 경합을 유도합니다.

---

## 2. 지표 산출 및 리스크 튜닝

### 2.1. 동적 임계치 설정 (Dynamic Thresholding)
- 테스트 환경에서의 민감한 리스크 탐지를 위해 `CMax`(최대 커넥션) 등의 상수를 실제 운영 환경보다 낮게 설정하여 조기 위험 감지 능력을 확보합니다.

### 2.2. 보수적 TPS 산출 공식
불확실한 운영 환경에 대비하여 다음과 같은 가중치 공식을 사용합니다.
- **공식**: $\lambda_{final} = \max(\lambda_{curr}, \lambda_{avg\_1h} \times 1.2, \lambda_{peak\_24h} \times 0.8)$
- **의미**: 실시간 트래픽뿐만 아니라 과거의 평균과 피크 상황을 모두 고려하여 '최악의 시나리오'를 가정합니다.

---

## 3. PostgreSQL 호환성 설계 (`internal/db/`)

### 3.1. 버전별 통계 뷰 대응
- PostgreSQL 14 이후 버전에서 변경된 통계 뷰 구조를 반영합니다. (예: `pg_stat_statements_info` 활용)
- 누적 지표의 리셋(Reset) 상황을 감지하여 델타 계산 시 발생할 수 있는 음수 값을 방지하는 방어 로직을 포함합니다.

### 3.2. 대소문자 구분 없는 테이블 매칭
- 쿼리 텍스트 내의 테이블 이름을 파싱할 때 대소문자 구분을 없애(Case-Insensitive), 실제 스키마와의 매칭 정확도를 높였습니다.

---

## 기술 요약: 시뮬레이션 워크플로우
1. **Load Generator**: 설정된 시나리오에 따라 `orders`, `products` 테이블에 지속적인 부하 유발.
2. **Agent**: 통계 뷰를 실시간 분석하여 델타 기반의 테이블별 정밀 지표 수집.
3. **Analyze CLI**: 수집된 지표를 바탕으로 현재 트래픽 상황에서 DDL이 미칠 영향을 수치화.
4. **Validation**: 10만 건 이상의 대형 테이블 변경 시 **Danger** 등급이 정상적으로 부여되는지 확인하여 장애 예방 능력 검증.
