# 테스트 케이스 확장 실험 진행 기록 - 2026-06-20

## 목적

DDL별 사전 판단과 실제 실행 결과 비교를 확장하기 위해 DDL 6개와 부하 3단계를 조합하여 실험한다. 각 DDL 실행 전에는 benchmark DB를 초기화하여 이전 DDL의 인덱스, 컬럼 변경, 제약조건이 다음 실험에 영향을 주지 않도록 한다.

## 공통 설정

| 항목 | 값 |
|---|---|
| workload | `orders_mixed` |
| 대상 테이블 | `orders` |
| 기본 데이터 | 초기 100,000 orders + 추가 900,000 orders |
| 총 orders 규모 | 약 1,000,000 rows |
| duration | 30초 |
| warmup | 8초 |
| DB 초기화 | 각 DDL 실행 전 수행 |

## 부하 설정

| Target TPS | Clients | Threads |
|---:|---:|---:|
| 100 | 4 | 2 |
| 1000 | 8 | 4 |

## 진행 상태

- 시작 시각: 2026-06-20
- 실행 범위: baseline 3회 + DDL 18회
- RunTag: `expand_20260620`
- 1차 실행: Windows PowerShell 실행 정책으로 `.ps1` 직접 실행이 차단되어 실패하였다. 실험 로직 또는 DB 상태 문제는 아니며, `powershell -ExecutionPolicy Bypass -File` 방식으로 재실행한다.
- 2차 실행: `powershell -ExecutionPolicy Bypass -File` 방식으로 baseline 3회와 DDL 18회를 모두 완료하였다.

핵심 결과는 다음과 같다.

- DDL-3 일반 인덱스 생성은 실제 P99 응답 지연을 크게 증가시켜 Warning 또는 Danger로 판정되었다.
- DDL-5 NOT NULL 직접 설정은 기존 데이터의 NULL 값 때문에 DDL 실행 자체가 실패하여 Danger로 판정되었다.
- DDL-1 nullable 컬럼 추가, DDL-2 동시 인덱스 생성, DDL-4 컬럼 타입 변경, DDL-6 CHECK 즉시 검증은 이번 실측 기준에서는 Safe로 판정되었다.
- MigraGuard는 18개 조건 중 16개를 Danger로 판단했으며, 이 중 10개는 실측 Safe였다. 따라서 현재 모델은 위험을 놓치지 않는 방향으로 보수적으로 동작하지만 false positive가 많다.
