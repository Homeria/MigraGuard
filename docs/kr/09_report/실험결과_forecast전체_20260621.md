## 2. 추천 정책

Forecast 추천 정책은 다음과 같다.

| 조건 | 해석 |
|---|---|
| Safe 시간대 존재 | 가장 낮은 RiskScore의 Safe 시간대를 일반 추천 |
| Safe 없음, Warning 존재 | 가장 낮은 RiskScore의 Warning 시간대를 조건부 추천 |
| Danger만 존재 | 추천 가능한 실행 시간 없음 |

Warning 조건부 추천은 “안전한 시간”을 의미하지 않는다. 실행해야 한다면 추가 승인, 모니터링 강화, 롤백 준비가 필요한 상대적 저위험 후보를 의미한다.

## 4. 해석

Forecast 결과는 세 가지 유형으로 나뉘었다.

첫째, DDL-1과 DDL-2는 현재 시점 분석에서는 Danger였지만 24시간 forecast에서는 Safe 시간대가 존재하였다. 이는 현재 작업 부하에서는 위험하게 보이더라도, 낮은 요청량과 낮은 P99 응답 지연이 예상되는 시간대에는 실행 후보를 제시할 수 있음을 보여준다.

둘째, DDL-3은 Safe 시간대가 없고 Warning 시간대만 존재하였다. MigraGuard는 02:00을 조건부 추천 시간으로 제시하였다. 이는 일반 인덱스 생성처럼 쓰기 차단 가능성이 있는 DDL은 낮은 부하 시간대라도 안전하다고 단정하지 않고, 추가 승인과 모니터링이 필요한 후보로 제시한다는 의미이다.

셋째, DDL-4, DDL-5, DDL-6은 24개 시간대 모두 Danger로 계산되어 추천 가능한 시간이 없었다. 이 결과는 강한 잠금, 테이블 재작성 가능성, 기존 데이터 검증 위험이 큰 DDL은 단순히 실행 시간대를 바꾸는 것만으로 해결되지 않을 수 있음을 보여준다. 이러한 DDL은 DDL 분할, 단계적 검증, 중단 마이그레이션 또는 온라인 변경 전략을 먼저 검토해야 한다.

## 5. 한계

이번 forecast는 실제 24시간 운영 데이터를 관측한 것이 아니라 시간대별 예상 작업 부하 시나리오를 사용하였다. 또한 시간대별 활성 커넥션과 복제 지연은 세밀하게 변화시키지 않았으므로, 추천 시간은 실제 배포 시각을 자동 확정하는 결과가 아니라 상대적으로 낮은 위험 후보로 해석해야 한다.

또한 현재 모델은 DDL-4, DDL-5, DDL-6을 모든 시간대에서 Danger로 판단하였다. 실제 실행 실험에서는 DDL-4와 DDL-6이 큰 P99 증가 없이 성공했으므로, forecast에서도 DDL 유형별 세부 비용과 PostgreSQL 최적화 차이를 더 정교하게 반영할 필요가 있다.
